# ZERO LANCE 0.1 — 첫 플레이어블 구현 및 검수 보고

작성: 2026-09-10

## 범위와 판정

기획서의 단계별 진행 지침에 따라 1스테이지 플레이어블과 성능 측정 기반을 구축했습니다. **전체 프로젝트 완료 또는 M0 통과 판정은 아닙니다.** 연결된 실기 장치가 없으므로 iOS/안드로이드의 실제 조작·열화·GPU 메모리 검증을 미결로 남깁니다.

원본 문서는 사용자가 지정한 루트가 아닌 `doc/PROJECT_ZERO_LANCE_개발프롬프트.md`에서 발견했습니다. 원본은 수정하지 않았습니다. 요구한 Vite/React/Three.js 구성을 유지하기 위해 Sites의 vinext 기본 템플릿으로 교체하지 않았습니다.

## 동작하는 게임 루프

1. 격납고 → 무기/크레딧 선택 → 스테이지 1 출격.
2. 이동/사격 → 적 편대/사수/캐리어/중형 적 → 파워업과 옵션 회수.
3. 스테이지 중 오버드라이브 획득 → 적 격파로 재충전.
4. 180초 후 GATEKEEPER → 독립 포탑 4기 → HP 60%/25%에서 패턴 전환.
5. 보스 격파 또는 제한시간 도주 → 결과 화면 → 재도전/격납고.
6. 기체 전멸 → 10초 컨티뉴 → 크레딧 소진/미응답 시 GAME OVER.

스테이지 2·3 카드에는 개발 예정 표시를 적용했고 선택 동작을 제공하지 않았습니다. 온라인 랭킹이나 인증을 흉내 내는 가짜 데이터를 사용하지 않았습니다.

## 검증 결과

- TypeScript strict 및 프로덕션 빌드 성공.
- ESLint 통과, 명시적 `any` 없음.
- Vitest 20개: 풀 고갈/재사용, 공간 해시, swept 충돌, 결정론, 경계, 입력 기록, 일시정지, 컨티뉴, 실드, 캐리어 보상, 기술 충전, 옵션 모드, 보스 전환/도주, 스트레스 풀, 그레이즈, 재시작.
- Playwright 3개 흐름: 출격/무기 선택/이동/모드/설정/일시정지, 보스 훈련/탄막 슬라이더, 모바일 크기/회전 정지.
- 테스트 환경에서 WebGPU와 강제 WebGL 2 모두 구동 확인.
- npm audit: 취약점 0건. Vitest를 4.1.11로 갱신해 mocker 관련 취약 의존성을 제거했습니다.
- JS gzip 약 353KB, CSS gzip 약 8KB. 원본의 코어 JS 900KB 예산 이내. 네트워크 4G 조건의 3초 목표는 아직 미측정.

### 데스크톱 성능

원본 결과는 `validation/desktop-performance.json`입니다. NVIDIA GeForce RTX 3070 / Windows / Chromium / WebGPU / 1440×810 / HIGH / 1,500발 / 20기 / 블룸 ON 조건으로 측정했습니다. 숫자를 모바일 결과로 해석하면 안 됩니다.

첫 측정은 60.0 FPS, 57 draw calls, JS heap 약 32~52MB였습니다. 화면 간격 약 16.67ms는 60Hz 주기의 값이며 GPU 실행시간 또는 CPU 작업시간 16.67ms라는 뜻이 아닙니다. 최종 변경 후 재측정한 원본 JSON을 우선합니다.

## 발견하고 수정한 문제

- Indexed/non-indexed 적 형상을 혼합 병합하여 null geometry가 발생하던 문제: 형식을 정규화하고 생성 실패를 명시적으로 검사했습니다.
- 누적 render calls를 FPS 화면의 draw calls로 사용하던 문제: 프레임마다 info를 reset하고 drawCalls를 표시합니다.
- 저프레임에서 짧은 keydown/keyup이 사라질 수 있던 문제: 입력 에지 비트를 다음 틱까지 보관합니다.
- 리플레이에 입력 에지를 별도 Uint16Array로 보관합니다. 이동 비트와 터치 델타는 기존 Float32Array에 유지합니다.
- 초기화 도중 화면을 해제했을 때 캔버스가 남는 경우를 정리했습니다.
- 고속 탄환 충돌은 이동 선분으로 판정해 작은 히트박스를 통과하는 현상을 방지합니다.

## 미완성 항목과 사양 차이

다음 항목은 구현 완료로 주장하지 않습니다.

1. **에셋 품질:** 현재 모델은 절차적으로 생성한 원본 기하 형상입니다. 8~12k 플레이어 tris 및 glTF/Meshopt/KTX2 최종 제작 규격, 아트 디렉터 검수는 미완료입니다. 런타임 게임 텍스처에 PNG/JPG를 사용하지 않습니다. PWA 아이콘만 PNG입니다.
2. **후처리:** TSL 블룸/원근/PBR/림 발광/화면 흔들림 구현. MRT emissive 분리, LUT, 열왜곡, radial blur, 볼류메트릭, SSR, GPU 파티클, 동적 그림자 품질 프리셋은 미구현입니다.
3. **할당량:** 탄환/엔티티 풀과 충돌은 사전 할당 구조입니다. UI는 10Hz snapshot 객체를 생성하며 Three.js와 브라우저 내부 할당도 존재합니다. 전체 프레임 **0 bytes GC** 조건은 검증되지 않았고, 힙 회수도 관찰됩니다. 이를 0이라고 보고하지 않습니다.
4. **무기:** 3계열 8레벨과 LASER 차지샷은 동작합니다. Lv.7 잔류 필드, Lv.8 히트 폭발, 미사일 지면 폭발 같은 모든 레벨별 특성은 미완성입니다.
5. **특수기술:** 1스테이지에서 OVERDRIVE만 획득 가능합니다. 나머지 기술의 숫자/부분 로직은 향후 연결 기반이며 최종 작동·획득·교체 검수가 완료된 기능이 아닙니다.
6. **콘텐츠:** 1스테이지/보스 훈련만 제공. 스테이지 2~6, 이동 지형, 방향 전환, 보스 러시, 스테이지 에디터 미구현.
7. **네트워크:** Supabase 로그인/회원가입/서버 발급 시드/세션 토큰/스코어 검증/RLS/이력/랭킹 미구현. 게스트 기록은 이번 실행의 메모리에만 저장합니다.
8. **결정론:** 동일 빌드·시드·입력에 대해 테스트했습니다. 서버 재생기나 다른 JS 엔진 간 비트 단위 동일성은 미검증입니다. 입력 버퍼는 600초이며 초과를 플래그로 표시합니다.
9. **튜닝:** 편대/적/무기/핵심 수치는 JSON입니다. 보스 패턴과 시각 표현에는 코드 상수가 남아 있어 전체 데이터화를 완료해야 합니다. 공간 해시는 화면 바깥 진입과 큰 적의 경계 조회를 위해 24×14 셀로 확장했습니다.
10. **사운드:** 오리지널 합성 BGM/SFX 구현. 최종 스테이지별 오디오 제작, Opus/AAC 에셋, 32채널 최종 믹싱은 미완료입니다.
11. **접근성/입력:** 기본 키보드/터치/게임패드 지원. 키 리매핑, 터치 버튼 크기 설정, 별도 색맹 팔레트, iOS 홈화면 설치 안내의 전체 검수는 남아 있습니다.
12. **PWA:** 프로덕션 서비스 워커, 매니페스트, 아이콘 생성 완료. 장치별 설치 UX와 오프라인 복귀 QA는 별도 검증이 필요합니다.

## 다음 스프린트

M0 실기에서 탄 1,500/3,000/4,000과 각 화질을 60초씩 측정하고 CPU/GPU/GC 프로파일을 분리합니다. 그 결과로 렌더러 병목과 임계치를 정한 후 glTF/KTX2 최종 기체, 전투 피드백, 전체 무기/기술 동작을 완성합니다. 이 게이트를 통과하기 전 6스테이지 양산으로 M0 검수를 대체하지 않습니다.

기술 참고: [Three.js WebGPURenderer](https://threejs.org/docs/pages/WebGPURenderer.html), [TSL BloomNode](https://threejs.org/docs/pages/BloomNode.html), 설치된 three@0.186.0 소스의 Info/RenderPipeline API.
